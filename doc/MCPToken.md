# MCP 访问令牌与端点鉴权

## 概述

Easy MCP 对外提供的 MCP 传输端点（SSE 与 Streamable HTTP）由**访问令牌（Token）**保护。令牌在数据库中管理，每个令牌**绑定一组工具**，决定了使用该令牌的 MCP 客户端能**列出和调用哪些工具**。

令牌鉴权与 Web 控制台的 JWT 登录是**两套独立机制**：

- 控制台 / 管理 API：用户名密码登录换取 JWT（短期，交互式）
- MCP 端点：长期不过期的 Bearer 令牌（面向机器，写入 MCP 客户端配置）

## 鉴权规则（fail-open）

鉴权采用**未配置即放行**的宽松策略：

| 系统中的令牌情况 | MCP 端点行为 |
|---|---|
| 一个令牌都没有 | **开放**，不鉴权，可访问全部启用工具（向后兼容） |
| 存在 ≥1 个令牌 | **强制鉴权**，必须携带有效令牌；仅可访问该令牌绑定的工具 |

注意事项：

- 判定依据是「**是否存在任意令牌行**」。
- 令牌**不支持禁用**，吊销请直接删除该令牌；删除后即时失效。关闭鉴权需**删除全部令牌**。
- 令牌**未绑定任何工具**时，可通过鉴权但无任何工具权限（列表为空、调用被拒）。
- 升级部署后若未创建令牌，MCP 端点保持开放，现有客户端不受影响；需要收紧时再创建令牌。

## 受保护的 MCP 端点

| 端点 | 方法 | 说明 |
|---|---|---|
| `/sse` | GET | SSE 传输，全部授权工具 |
| `/sse-{tag}` | GET | SSE 传输，按标签过滤后再与令牌授权工具取交集 |
| `/messages/{path}` | POST | SSE 传输的客户端→服务端通道 |
| `/mcp` | POST | Streamable HTTP 传输，全部授权工具 |
| `/mcp-{tag}` | POST | Streamable HTTP 传输，标签过滤 ∩ 令牌授权工具 |

令牌通过下列任一方式传递（优先级从高到低）：

1. 请求头 `Authorization: Bearer <token>`（推荐）
2. 查询参数 `?token=<token>`（兼容无法自定义请求头的客户端）

鉴权失败返回 `401 Unauthorized`。

## 在控制台管理令牌

进入控制台左侧菜单「访问令牌」：

- **创建**：填写名称、描述，多选绑定工具。创建成功后会**弹窗展示完整令牌**，请复制并配置到客户端（令牌也可在列表中随时「显示/复制」）。
- **编辑**：修改名称/描述/绑定工具。
- **删除**：令牌不支持禁用，吊销即删除；删除后使用该令牌的 MCP 客户端立即失效。

令牌值形如 `emcp_xxxxxxxx...`。

## MCP 客户端接入示例

以 Cherry Studio / Claude Desktop 等支持自定义请求头的客户端为例，在 MCP Server 配置中填写：

- 地址：`http://<host>:<port>/mcp`（Streamable HTTP）或 `http://<host>:<port>/sse`（SSE）
- 请求头：`Authorization: Bearer emcp_xxxxxxxx...`

按标签隔离时使用 `/mcp-<tag>` 或 `/sse-<tag>`，返回的工具为「标签过滤结果 ∩ 令牌绑定工具」。

### curl 自测

```bash
# 未带令牌（系统已配置令牌时返回 401）
curl -i -X POST http://localhost:8000/mcp

# 携带令牌
curl -i -X POST http://localhost:8000/mcp \
  -H "Authorization: Bearer emcp_xxxxxxxx..."
```

令牌的增删改查复用控制台的 JWT 鉴权，详见 [接口说明.md](接口说明.md) 的「MCP 访问令牌接口」章节。

## 安全建议

- 一个客户端/团队一个令牌，按最小权限只绑定其需要的工具，便于按需吊销。
- 令牌等同长期凭证，请勿提交进代码库或日志；泄露后在控制台删除该令牌即可立即失效。
- 生产环境建议同时做网络层收敛（反向代理 / 防火墙），与令牌鉴权形成纵深防御。
